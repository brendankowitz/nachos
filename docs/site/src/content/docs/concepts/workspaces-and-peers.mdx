Workspace and peer CRUD are implemented in the source MVP.

A workspace is a namespace for related memory. A peer identifies a participant
within that workspace: an agent, a person, or another conversational actor.
A peer is not automatically an authenticated identity.

Workspace boundaries separate data; authentication and grants must establish
which caller may use each boundary. Choosing an identifier is not authorization.
The design treats identifiers as case-sensitive.

Sessions bring peers together for an interaction. The same peer may
participate in more than one session without merging those sessions' message streams.

Memory is kept per pair of peers: what one peer (the observer) has concluded about another
(the observed), or about itself. Which pairs exist depends on each peer's `observe_me` and
`observe_others` settings; see [Observation model](/nachos/concepts/observation-model/).
